### The two findings this table supports

**Finding 1 — recovery succeeded only where the failure was mechanical.**
Every recovery observed in this study (`django__django-11039`, `django__django-11583`, `django__django-11620`)
was a format-class failure whose patch representation had been repaired. Not one
of the four logic-class failures was resolved by any strategy in any round.
Changing *how the edit was expressed* moved outcomes; changing *what the model
was told about its failure* did not.

**Finding 2 — richer post-failure information produced identical outcomes.**
On `django__django-11019` the sub-test score is identical under all three
strategies and both rounds:

| Condition / round | F2P | P2P broken |
|---|---|---|
| Baseline (unified diff) | 0/16 | 33 |
| Blind Retry R1 | 6/16 | 0 |
| Blind Retry R2 | 6/16 | 0 |
| Reflection-only R1 | 6/16 | 0 |
| Reflection-only R2 | 6/16 | 0 |
| Diagnose+Revise R1 | 6/16 | 0 |
| Diagnose+Revise R2 | 6/16 | 0 |

The retrofit alone moved this task from 0/16 with 33 regressions to 6/16 with
none. Reflection and diagnosis then added nothing on top of blind retry, while
costing roughly three times the input tokens (`data/config.md`).

**Counter-signal worth reporting.** On `django__django-11283`, Diagnose+Revise
broke **8 PASS_TO_PASS tests** where Blind Retry broke none.
On this task the additional diagnostic context made the patch more damaging,
not less. Chapter 5 should report this rather than average it away.
